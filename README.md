# 푸드홀(인제대학교) 온라인 메뉴판

밥심 · 만권화밥 · 후루룩찹찹 3개 매장의 메뉴를 소개하는 정적 홈페이지입니다.
HTML / CSS / 순수 JavaScript만 사용했으며, 별도의 빌드 과정 없이 그대로 Netlify에 올리면 됩니다.

## 1. 로컬에서 확인하는 방법

`index.html`은 CSS와 JavaScript를 전부 내장한 **독립 실행형 파일**입니다.
별도의 css/js 파일을 불러오지 못하는 미리보기 환경에서도 깨지지 않도록,
`index.html` 파일 하나만 열어도 정상적으로 작동합니다.

브라우저에서 `index.html`을 더블클릭해서 바로 열어도 됩니다.
(로컬 서버가 있다면 아래처럼 실행해도 됩니다.)

```bash
cd 프로젝트폴더
python3 -m http.server 8000
```

이후 브라우저에서 `http://localhost:8000` 접속.

## 2. GitHub 업로드 방법

```bash
cd 프로젝트폴더
git init
git add .
git commit -m "init: 푸드홀 메뉴판"
git branch -M main
git remote add origin <본인의 GitHub 저장소 주소>
git push -u origin main
```

## 3. Netlify와 GitHub 연결 방법

1. [Netlify](https://app.netlify.com)에 로그인 후 `Add new site` → `Import an existing project` 선택
2. GitHub 계정 연결 후 방금 올린 저장소 선택
3. Build command는 비워두고, Publish directory는 `.`(루트)로 지정
   (이미 `netlify.toml`에 설정되어 있어 자동으로 인식됩니다)
4. `Deploy site` 클릭

## 4. 자동 배포 방법

위 방식으로 한 번 연결해두면, 이후 GitHub 저장소의 `main` 브랜치에
`git push`만 하면 Netlify가 자동으로 다시 배포합니다.

## 5. 메뉴 가격 수정 위치

`js/menu-data.js` 파일에서 수정하려는 메뉴의 `price` 값을 숫자로 바꾸면 됩니다.

```js
price: 7500,   // 이 숫자만 바꾸면 화면에 "7,500원"으로 자동 표시됩니다.
```

## 6. 품절 상태 수정 위치

같은 파일(`js/menu-data.js`)에서 해당 메뉴의 `soldOut` 값을 바꾸면 됩니다.

```js
soldOut: true,   // 품절일 때
soldOut: false,  // 판매 중일 때
```

## 7. 수정 후 index.html에 반영하는 방법

`index.html`은 `css/style.css`, `js/translations.js`, `js/menu-data.js`,
`data/breakfast-weekly-menu.js`, `js/app.js`의 내용을 그대로 담고 있는
독립 실행형 파일입니다.

위 파일 중 하나라도 수정했다면, 아래 명령을 한 번 실행해서
`index.html`에 최신 내용을 다시 합쳐 넣어야 화면에 반영됩니다.

```bash
python3 scripts/build-inline.py
```

실행 후 `index.html`을 다시 열어 확인하세요.
(이 스크립트는 배포에 필요한 빌드 과정이 아니라 로컬 편집을 돕는
선택적 도구입니다. Netlify에는 완성된 `index.html`만 그대로 올리면 됩니다.)

## 8. 천원의 아침밥 — 주간 메뉴 매주 업데이트 방법

밥심 화면의 "천원의 아침밥" 탭에는 오늘 날짜(한국 표준시 기준)에 해당하는
아침 메뉴만 자동으로 표시됩니다. 매주 다음 순서만 반복하면 됩니다.

1. 새로 받은 엑셀 주간 메뉴 스크린샷을 `images/breakfast/` 폴더에 저장합니다.
   (파일명 예시: `2026-09-07-weekly-menu.jpg`)
2. Claude(또는 Claude Code)에게 아래 문구와 함께 스크린샷을 첨부해서 전달합니다.

   > 첨부한 엑셀 주간 메뉴 스크린샷을 확인하고 천원의 아침밥 메뉴 데이터를
   > 업데이트해라. 메뉴명, 날짜, 요일, 메뉴 순서를 원본 그대로 입력하고
   > 추측하거나 메뉴명을 바꾸지 마라. 스크린샷은 주간 메뉴 원본 이미지로
   > 저장하고, 홈페이지에는 한국시간을 기준으로 오늘 메뉴만 글자로
   > 표시되게 해라. 기존 디자인과 다른 기능은 변경하지 말고 완료 후
   > 날짜별 입력 내용을 보고해라.

3. `data/breakfast-weekly-menu.js` 파일만 수정됩니다. (다른 화면 코드는
   건드릴 필요가 없습니다.)
4. `python3 scripts/build-inline.py` 실행 → `index.html` 갱신
5. Netlify에 배포
6. 월요일부터 금요일까지 날짜별로 메뉴가 정확히 나오는지 확인

`data/breakfast-weekly-menu.js` 데이터 구조:

```js
const BREAKFAST_WEEKLY_MENU = {
  weekStart: "2026-09-07",
  weekEnd: "2026-09-11",
  sourceImage: "images/breakfast/2026-09-07-weekly-menu.jpg",
  days: {
    "2026-09-08": {
      rice: { ko: "쌀밥" },
      soup: { ko: "콩나물국" },
      main: { ko: "돼지불고기" },
      side1: { ko: "계란말이" },
      side2: { ko: "콩나물무침" },
      kimchi: { ko: "배추김치" }
    }
    // 날짜별로 계속 추가
  }
};
```

- 각 항목은 `{ ko: "..." }`만 있어도 정상 작동합니다 (다른 언어는 자동으로
  한글로 대체 표시됩니다). 번역까지 넣고 싶으면 `en` / `zh` / `vi` / `mn`
  키를 추가하면 됩니다.
- 데이터가 없는 날(주말 등)은 화면에 "오늘은 운영하지 않습니다" 문구가
  자동으로 표시됩니다.
- `sourceImage`가 없으면 "주간 메뉴 원본 보기" 버튼 자체가 화면에
  나타나지 않습니다.

## 9. 천원의 아침밥 — 오늘의 메뉴 평가

학생이 "천원의 아침밥 → 오늘의 메뉴" 화면에서 캐릭터 하나를 터치하면
별도 버튼 없이 즉시 만족도가 저장되는 기능입니다. 같은 기기에서는
하루(한국시간 기준) 1회만 평가할 수 있습니다.

Firebase(babsim-46284 프로젝트)와 이미 연결되어 있고, Firestore 보안 규칙도
적용되어 있습니다. 규칙 전체 내용은 `js/firebase-config.js` 파일 맨 위
주석에 있습니다 — 컬렉션을 추가하거나 규칙을 바꿀 일이 있으면 그 주석부터
확인하세요.

**Firebase가 어떤 이유로든 연결되지 않은 상태여도 학생 화면은 정상
작동합니다.** 평가를 누르면 그 기기의 브라우저(localStorage)에만 하루
1회 제한이 적용되고 "감사합니다!"가 표시되지만, 관리자 페이지 통계에는
집계되지 않습니다.

## 10. 관리자 페이지

`admin.html`을 열면 통계 열람용 암호(기본값 `foodhall2026`)를 입력한 뒤
4개 탭을 오갈 수 있습니다: **대시보드 / 메뉴 평가 / 언어 통계 / 주간메뉴 관리**.

암호는 `js/admin.js` 맨 위 `ADMIN_PASSPHRASE` 값을 바꾼 뒤
`python3 scripts/build-inline.py`를 다시 실행해서 꼭 변경하세요.
이 암호는 화면 접근을 막는 최소한의 장치일 뿐, 실제 보안은
Firestore 보안 규칙이 담당합니다.

`admin.html`도 `index.html`과 마찬가지로 CSS/JS를 전부 내장한
독립 실행형 파일입니다. `css/admin.css`, `js/admin.js`를 수정했다면
`python3 scripts/build-inline.py`를 실행해야 `admin.html`에 반영됩니다
(직접 `admin.html`을 열어서 수정하지 마세요 — 다음 빌드 때 덮어써집니다).

### 10-1. 대시보드

오늘 접속자·평가 참여·평균평점·최다 선택 언어 요약과, 오늘 평가 분포·
오늘 언어 선택 분포·최근 7일 접속자 추이 그래프를 한 화면에서 봅니다.
"오늘 접속자"는 서버 로그 기반 트래픽 집계가 아니라, 아래 10-3
언어 통계 문서(기기당 하루 1개)의 개수를 사용한 근사치입니다.

### 10-2. 메뉴 평가

- 오늘 평가(참여자·평균평점·긍정평가 4·5점·부정평가 1·2점·5단계 분포)
- 기간 선택(오늘 / 최근 7일 / 이번 달 / 날짜 직접 선택)에 따른 날짜별 결과 표
  (날짜를 클릭하면 그 날짜의 5단계 분포로 전환)
- 최근 7일 · 최근 30일 평균평점 변화 추이 그래프

식사인원 대비 평가 참여율은 이 저장소에 기존 방문자/식사인원 집계
기능이 없어 구현하지 않았습니다. (임의로 만든 데이터를 쓰지 않기 위함
— 필요하시면 별도로 방문자 집계 기능부터 추가해 드릴 수 있습니다.)

### 10-3. 언어 통계

학생 화면에 별도 언어 선택 UI를 추가하지 않고, 기존 언어 버튼(헤더의
한국어/中文/Tiếng Việt/English/Монгол)에 그대로 연동됩니다. 방문 시점과
언어를 바꿀 때마다 `languageStats` 컬렉션에 `날짜_기기ID`를 문서 ID로
저장하므로, 같은 기기가 하루에 여러 번 들어오거나 언어를 여러 번 바꿔도
그날 문서는 항상 1개이고 **그날의 최종 선택 언어**만 남습니다. (몇 번
바꿨는지는 `changeCount` 필드에 함께 남아 있어, 나중에 "변경 횟수" 통계를
추가하고 싶을 때 바로 쓸 수 있습니다.)

관리자 페이지에서는 오늘 / 최근 7일 / 이번 달 / 날짜 직접 선택 기간에 대해
언어별 인원수·비율을 막대 그래프로 봅니다.

### 10-4. 주간메뉴 관리

관리자가 "천원의 아침밥"의 요일별 메뉴를 이미지 자동인식으로 등록하거나
직접 입력하는 곳입니다. **통계 열람 암호와는 별개로, Firebase
Authentication 로그인이 한 번 더 필요합니다** (아래 10-5 참고 — 아직
설정 전이면 이 탭에 로그인 폼만 보이고 편집 화면은 잠겨 있습니다).

두 가지 등록 방식은 서로 독립적으로 동작하며(한쪽이 실패해도 다른
쪽은 그대로 쓸 수 있습니다), 결과는 항상 같은 화면(방식 2의
카드 목록)에서 확인·수정한 뒤 저장합니다.

- **방식 1 · 이미지로 자동 인식**: 엑셀 주간 메뉴 스크린샷을 올리고
  "이미지 분석하기"를 누르면, 서버(Netlify Function)가 이미지를 분석해서
  요일별 **일반식 / 간편식** 메뉴명을 자동으로 채워줍니다. 이미지에 실제로
  적힌 글자만 옮기도록 지시되어 있고, 글자가 흐릿하거나 확신이 서지 않는
  항목은 **빨간 배경 + "확인 필요" 표시**로 남습니다 — 관리자가 직접 읽고
  고치거나 확정해야 합니다(입력칸을 수정하면 표시가 자동으로 사라짐).
  분석 결과는 바로 저장되지 않고, 아래 방식 2와 같은 화면에 채워지기만
  합니다.
- **방식 2 · 직접 입력 / 인식 결과 확인**: 주 시작일(월요일)을 고르면
  월~금 5개 카드가 나옵니다. 실제 배식표와 같은 구조로, 카드마다
  **일반식 / 간편식** 두 목록으로 나뉘어 있고 각각 메뉴를 자유롭게
  추가/삭제할 수 있습니다. 방식 1의 분석 결과도 이 화면에 채워지므로,
  이미지 없이 처음부터 직접 입력할 수도 있고 분석 결과를 그대로 고쳐서
  쓸 수도 있습니다. 요일마다 "운영"(휴무 시 해제) 체크박스도 있습니다.
  - **엑셀 붙여넣기**: 각 카드에 작은 붙여넣기 칸이 있습니다. 엑셀에서 그
    요일의 일반식·간편식 두 칸(여러 줄)을 함께 선택해 복사한 뒤 그대로
    붙여넣고 "붙여넣기 적용"을 누르면 두 목록에 자동으로 나뉘어 채워집니다
    (탭 구분 2번째 칸이 없으면 전부 일반식으로 채워짐).
- **임시저장 / 번역 확인 / 게시 확정**: "임시저장"은 관리자 화면에만
  남고 학생 화면에는 절대 반영되지 않습니다(초안 확인용). 내용을 다
  확인했으면 **"번역 확인"**을 눌러 한글 메뉴명을 5개 언어(중국어/
  베트남어/영어/몽골어)로 자동 번역한 결과를 미리 봅니다 — 번역이 안 된
  항목은 빨간 배경의 **"번역 대기"**로 표시됩니다. 내용을 확인했으면
  **"게시 확정"**을 눌러야 학생 화면에 실제로 반영됩니다. 이미지를 새로
  올렸다면 이때 Firebase Storage에도 업로드됩니다. 같은 메뉴명은
  `menuTranslations` 사전에 캐시되어 다음 주에 다시 번역하지 않습니다.
  번역이 없는 메뉴는 학생 화면에서 자동으로 한국어로 대체 표시됩니다
  (빈 칸이나 "undefined"가 뜨지 않음).
- **번역 다시 실행**: 번역 서버 장애 등으로 한글로만 게시된 메뉴가
  있으면 "번역 다시 실행" 버튼이 안내와 함께 나타납니다. 눌러서 다시
  번역을 받은 뒤 "게시 확정"을 한 번 더 누르면 번역이 채워집니다.
- **오늘·내일 화면 표시**: 학생 화면(오늘/내일 카드)에는 항상 **글자
  메뉴만** 표시되고, 주간표 이미지가 카드 안에 통째로 들어가는 일은 없습니다.
  운영일인데 아직 메뉴가 등록되지 않은 날은 "메뉴를 준비 중입니다",
  주말이거나 관리자가 휴무로 지정한 날은 "오늘/내일은 운영하지 않습니다"로
  구분해서 표시됩니다. 등록해 둔 주간표 원본 이미지는 "주간 메뉴 원본
  보기" 버튼을 눌렀을 때만 팝업으로 보여줍니다(확대/축소, 닫기 지원).
- 학생 화면(`index.html`)은 페이지를 열 때마다 이 데이터를 최신 상태로
  불러옵니다. Firebase에 게시된 데이터가 없으면 기존처럼
  `data/breakfast-weekly-menu.js` 정적 파일 내용이 그대로 쓰입니다
  (100% 하위 호환 — 이 파일과 매주 스크린샷을 Claude에게 보내 갱신하던
  기존 8번 방식도 계속 그대로 쓰실 수 있습니다).

### 10-4-1. 이미지 자동 인식(OCR) 서버 설정 — `GEMINI_API_KEY`

방식 1(이미지 자동 인식)은 브라우저가 아니라 서버(Netlify Function,
`netlify/functions/parse-weekly-menu.js`)에서만 AI를 호출합니다.
Google Gemini API 키가 브라우저 코드에 절대 들어가지 않도록 하기 위한
구조이며, 관리자 로그인 여부(Firebase ID 토큰)도 이 함수 안에서 다시
한번 서버 측에서 확인합니다 — 로그인하지 않은 일반 방문자는 이 함수를
호출할 수 없습니다.

1. https://aistudio.google.com 에서 Gemini API 키를 발급받습니다.
2. Netlify 대시보드 → 해당 사이트 → **Site configuration → Environment
   variables** → "Add a variable" → Key: `GEMINI_API_KEY`, Value: 발급받은 키.
3. 값을 저장하면 다음 배포부터 바로 적용됩니다(코드 변경 불필요).

`GEMINI_API_KEY`를 아직 등록하지 않았어도 사이트는 정상 동작합니다.
"이미지 분석하기"를 누르면 "아직 설정되지 않았습니다"라는 안내만 뜨고,
방식 2(직접 입력)는 이 설정과 무관하게 그대로 사용할 수 있습니다.

### 10-4-2. Google AI Studio / Gemini 장애 대비

주간메뉴 등록 기능 전체가 Gemini 장애 때문에 멈추지 않도록 아래처럼
설계되어 있습니다.

- **홈페이지는 Gemini를 절대 호출하지 않습니다.** 오늘·내일 메뉴는
  Firestore에 이미 저장된 내용을 읽기만 하므로, Gemini가 완전히
  다운되어도 학생 화면과 기존 기능(평가, 방문자·언어 통계, 무료 콜라
  쿠폰, 카카오톡 연결 등)은 전혀 영향받지 않습니다.
- Gemini 호출은 **관리자가 게시할 때만** 일어나고(이미지 분석 1번,
  번역 1번), 한 번 호출은 최대 20초까지 기다린 뒤 2초 간격으로 최대
  2번까지만 자동 재시도합니다. 그래도 실패하면 관리자 화면에
  "자동 메뉴 분석에 실패했습니다. 잠시 후 다시 시도하거나 직접 입력해
  주세요."라고 뜨고, **다시 분석 / 직접 입력으로 전환 / 이미지 다시
  선택** 세 버튼이 나타납니다. 이때 업로드한 이미지와 입력하던 내용은
  전혀 지워지지 않습니다.
- **번역 서버가 완전히 막혀 있어도 게시할 수 있습니다.** "번역 확인"을
  누르면 번역이 안 된 항목은 빨간 배경의 "번역 대기"로 표시되고,
  그 상태에서 "게시 확정"을 눌러도 정상적으로 게시됩니다 — 그 메뉴는
  학생 화면에 한국어로만 보입니다(빈 칸이나 "undefined"는 절대
  뜨지 않음). 나중에 "번역 다시 실행"으로 처리하면 됩니다. 이미
  번역된 적 있는 메뉴명은 `menuTranslations` 사전을 먼저 확인하므로,
  Gemini가 막혀 있어도 예전에 번역해 둔 메뉴는 정상적으로 표시됩니다.
- **이미지 분석을 시작하기 전 입력 중이던 내용은 브라우저에 자동
  저장됩니다.** 새로고침하거나 실수로 페이지를 닫아도 "이전에 작성
  중이던 내용을 복원했습니다" 안내와 함께 그대로 돌아옵니다(다시
  시작하려면 "새로 시작" 버튼).
- 이미지 분석이 실패해도 방식 2(직접 입력)는 완전히 독립적으로
  동작하며, 어느 쪽으로 등록하든 게시 전 확인 절차와 5개 언어 번역은
  동일하게 적용됩니다.
- 예상치 못한 오류가 나도 관리자 페이지가 흰 화면이 되지 않도록 전역
  안전망을 넣어 뒀습니다 — 오류가 나면 화면 위에 작은 배너만 뜨고,
  이미 그려진 화면은 그대로 유지됩니다.

### 10-5. Firebase Authentication 설정 (주간메뉴 등록에 필수)

주간메뉴 "쓰기"(등록·수정·삭제, 이미지 업로드)는 통계 열람 암호만으로는
할 수 없습니다. Firestore 규칙에서 `request.auth != null`(로그인된
사용자)만 쓰기를 허용하도록 만들어 두었기 때문입니다 — 관리자 비밀번호를
코드에 그대로 적어두지 않기 위한 조치입니다.

1. https://console.firebase.google.com/project/babsim-46284/authentication
   접속 → "Sign-in method" 탭 → "이메일/비밀번호" 제공업체 사용 설정
2. "Users" 탭 → "사용자 추가" → 관리자로 쓸 이메일 + 비밀번호 1개 등록
3. `admin.html` → "주간메뉴 관리" 탭에서 그 이메일/비밀번호로 로그인

이 설정을 하기 전까지는 "주간메뉴 관리" 탭에 안내 문구만 보이고
등록·수정·삭제·업로드는 할 수 없습니다(학생 화면과 다른 탭들은 영향 없음).

### 10-6. 관련 파일

- `js/breakfast-rating.js` : 학생용 평가 위젯(캐릭터 SVG, 저장, 하루 1회 제한).
  평가 저장 시 그날 실제로 제공된 메뉴(`menuDate`/`mealType`/`menuNames`)도
  함께 기록해서, 관리자 페이지에서 어떤 날 어떤 메뉴에 대한 평가인지
  확인할 수 있습니다.
- `js/language-stats.js` : 언어 선택/방문 기록 (새 UI 없이 기존 언어 버튼과 연동)
- `js/weekly-menu-sync.js` : 관리자가 "게시 확정"한 주간메뉴(published 상태만)를
  학생 화면에 반영. 임시저장(draft)은 반영하지 않습니다.
- `js/firebase-config.js` : Firebase 연결 설정(Firestore/Auth/Storage 헬퍼 포함)
- `netlify/functions/parse-weekly-menu.js` : 주간메뉴 이미지 인식(OCR)·번역을
  처리하는 서버 함수. `GEMINI_API_KEY`는 이 함수 안(서버)에서만 쓰이고
  브라우저에는 전달되지 않습니다. 관리자 로그인(ID 토큰) 검증도 이 함수가
  서버에서 다시 확인합니다.
- `admin.html`, `js/admin.js`, `css/admin.css` : 관리자 페이지
  (대시보드/메뉴 평가/언어 통계/주간메뉴 관리)
- `js/translations.js`의 `BREAKFAST_RATING_TEXT` : 평가 화면 다국어 문구
  (한국어/영어/중국어/베트남어/몽골어)
